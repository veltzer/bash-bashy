terminology

We use "activate" and "deactivate" for the names of the two main hooks of any plugin in bashy

each plugin defines an activate function, and usually a deactivate function, and registers them:
	register _activate_[plugin_name] _deactivate_[plugin_name]

Why are these functions prefixed by underscores?
Because they need to be called by bashy and not directly from the command line since
they expect variables by reference to be passed to them so calling them directly
will not work. This means that they need to be activated by bashy and only bashy.

Activation happens once, at shell startup, for every plugin enabled in bashy.list.
There is no on demand activation; open a new shell (or "exec bash") after changing
the list. Deactivation is on demand:
	$ bashy_deactivate [name]
if a plugin has no 'deactivate' function bashy says so.

Bashy keeps the state of each plugin (found, loaded, result, error, timing) in
associative arrays keyed by plugin name, so any plugin can be looked up without
scanning. The only plain array is the run order, which is what bashy.list gives.

A plugin can also supply an installer for the tool it wraps. That was once discussed as a
separate kind of "download plugin" with its own folder and contract; it ended up as a
third hook on the same plugin instead:
	register_install _install_[plugin_name]
	$ bashy_install [name]
An installer is a plain bash function with no parameters, and the core/install.sh and
core/download.sh helpers give every installer the same reporting, caching and checksum
handling.
